# 技术术语知识

cgroup_sched_plugin 模块核心技术框架和机制的知识定义，涵盖价值认知、原理、使用方式和代码关联。

## ffrt 队列串行化并发模型

### 解决的问题（Problem）

| 子维度  | 内容                                                                                |
| ---- | --------------------------------------------------------------------------------- |
| 业务痛点 | `Supervisor` 进程模型缓存被多个事件并发修改，传统加锁方案在高频事件场景下易产生锁竞争与优先级反转，延迟不可控                   |
| 技术目标 | 实现无锁并发安全，保证进程模型一致性与事件处理顺序，同时满足低延迟响应需求                                            |

### 原理（Principles）

| 子维度  | 内容                                                                                                       |
| ---- | -------------------------------------------------------------------------------------------------------- |
| 核心机制 | 事件处理层 `CgroupEventHandler` 持有 ffrt 队列（`CgroupEventHandlerQueue`），所有 `Handle*` 处理与策略调整通过 `PostTask` 串行化提交，队列按提交顺序依次执行 |
| 关键流程 | 消息接收层 `DispatchResource` 查映射表 → 命中则 `PostTask` 投递到队列 → 事件处理层串行执行 payload 解析、状态更新、策略计算与下发                            |

### 使用方式（Usage）

| 子维度    | 内容                                                                                   |
| ------ | ------------------------------------------------------------------------------------ |
| 核心 API | `PostTask(func)` 提交异步任务；`PostTask(func, name, delay)` 提交延时任务；`PostTaskAndWait(func)` 同步等待；`RemoveTask(name)` 取消延时任务 |

### 代码关联（Code）

| 子维度  | 内容                                                                |
| ---- | ----------------------------------------------------------------- |
| 核心类  | `CgroupEventHandler`（`framework/sched_controller/include/cgroup_event_handler.h`） |

### 约束与限制（Constraints）

| 子维度  | 内容                                                  |
| ---- | --------------------------------------------------- |
| 系统限制 | 队列内任务必须非阻塞，阻塞任务会阻塞后续所有事件处理                          |
| 并发约束 | `Supervisor`/`Application`/`ProcessRecord` 状态变更必须在队列任务内执行，禁止跨线程访问 |

## 扩展库 dlopen 加载机制

### 解决的问题（Problem）

| 子维度  | 内容                                                                                  |
| ---- | ----------------------------------------------------------------------------------- |
| 业务痛点 | 上报、仲裁、事件分发、资源订阅等扩展能力由外部动态库提供，版本与产品形态差异大，硬编码依赖会导致编译期耦合                                |
| 技术目标 | 运行时按需加载扩展库符号，加载失败时安全降级，核心分组调度功能不受影响                                                  |

### 原理（Principles）

| 子维度   | 内容                                                                                                                                                  |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 核心机制 | 事件处理层的 `ResSchedUtils` 单例通过 `dlopen`/`dlsym` 加载两个扩展库：`libresschedsvc.z.so`（`LoadUtils`）与 `libcgroup_sched_ext.z.so`（`LoadUtilsExtra` 及 `LoadSyncResourceEx`），符号解析结果保存为成员函数指针 |
| 容错   | 加载失败或符号缺失时通过 `HiSysEventWrite` 上报 `INIT_FAULT` 故障事件并记录 `CGS_LOGW`/`CGS_LOGD`；每个回调封装对函数指针做空指针保护，缺失时安全返回                                                  |

### 使用方式（Usage）

| 子维度    | 内容                                                                                                                                                  |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 核心 API | `ReportDataInProcess`（进程内数据上报）、`ReportArbitrationResult`（仲裁结果回报）、`ReportSysEvent`（系统事件回报）、`ReportCallerEvent`（调用方事件回报）、`DispatchResourceExt`（异步扩展分发）、`DeliverResourceExt`（同步扩展分发）、`SubscribeResourceExt`/`SubscribeSyncResourceExt`（扩展资源订阅） |

### 代码关联（Code）

| 子维度  | 内容                                                                    |
| ---- | --------------------------------------------------------------------- |
| 核心类  | `ResSchedUtils`（`framework/utils/include/ressched_utils.h`）          |

### 约束与限制（Constraints）

| 子维度  | 内容                                                              |
| ---- | --------------------------------------------------------------- |
| 安全约束 | 扩展库符号缺失时禁止崩溃，须安全返回；禁止绕过扩展库直接调用资源调度服务的上报接口                       |
| 故障打点 | 加载失败须通过 HiSysEvent 上报 `INIT_FAULT`，包含模块名、场景名、错误信息三字段             |
